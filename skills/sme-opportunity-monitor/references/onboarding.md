# 安装、迁移与定时检查

本技能需要完整安装包。定位包根目录时，先查看本 `SKILL.md` 所在目录及其祖先目录是否存在 `runtime/bootstrap.py` 和 `templates/workspace/`。`install.py` 安装后的结构为 `SKILL_DIR/{SKILL.md,references/,runtime/,templates/,tools/}`，此时包根就是 SKILL_DIR；仓库或插件源码中，包根在 `skills/sme-opportunity-monitor/` 之外的祖先目录。仅复制技能的情况下，使用用户指定的完整仓库检出路径，不能猜作者电脑路径。

## 接收人员首次安装

1. 确认接收人的本地工作目录、负责范围 policy/tender/both 和显示姓名。用户未定位置时，可在其普通用户文档目录下建议新建“中小企业机会监测”；不要默认写插件缓存或源代码目录。若无法推断分工，先初始化 both 供手动试跑，建立定时任务前确认实际负责范围。
2. 定位本机可用 Python 3.10+；优先使用 Codex 的 `load_workspace_dependencies` 返回的 Python，也可使用本机已安装 Python。此流程不调用 OpenAI API，无需额外 API key。
3. 从已定位的完整包根运行 `runtime/bootstrap.py init --workspace <本机绝对路径> --scope <范围> --operator <姓名>`。已备妥本机证据路径的画像 JSON 可加 `--profile-import <本地画像JSON>`；跨电脑迁移优先使用团队私下提供的画像 ZIP：先初始化，再运行 `tools/profile_bundle.py unpack --bundle <私有画像ZIP> --workspace <本机绝对路径> --replace-profile`，之后运行 `tools/profile_bundle.py doctor --workspace <本机绝对路径>` 校验全部证据 SHA256。初始化模板可被该导入替换并备份；若本机已有真实画像先比较差异，未经明确选择不能静默加 `--replace-profile`。ZIP 不带旧台账、人员审核、账号或自动化 ID，不可上传公共仓库。随后运行 `runtime/bootstrap.py doctor --workspace <本机绝对路径>`。
4. 阅读新目录的 `profile.json` 和 `sources.json`。企业名称、业务、地区、已有资质及证据逐项区分已确认/待核；软件招标范围较广，履约区域仍待团队确认。通用样例不代表公司实际具备资质。可先做来源连通和展示试跑，但没有实际画像不能宣布匹配或完整配置通过。
5. 按 `手动试跑提示词.txt` 完成一次真实网页检查，保存 input、覆盖缺口、两份台账和人工复核包。演示 JSON 只能验证解析，不能当作真实发现。正常登录在接收人的浏览器完成；账号、验证码、Cookies、VPN 设置不从作者电脑迁移。需要个人处理的登录障碍只说明实际情况。
6. 展示试跑结果和人员每日怎么审。若用户已经要求安装并自动化，完成本机试跑后继续用以下规则登记定时任务；用户只要求安装或手动试跑时，不擅自建立定时任务。

升级使用 `runtime/bootstrap.py upgrade --workspace <本机绝对路径>`。已有画像、数据库和人员记录保留；规则发生本地修改时保留原文件、对照新版本再调整。升级程序不等于新查网站。安装后运行 doctor，确认工作区程序、版本与可读写路径。

## 在接收人的当前对话注册

必须用该 Codex 当前可用的 `automation_update` 工具及其实际 schema，不直接写 `automation.toml`、不复用别人账户/线程/自动化 ID、不把安装脚本输出当任务已经启动。没有该工具时，交付已渲染的提示词和待创建清单，并明确“本机程序已安装，定时任务尚未建立”。不能声称已自动运行。

时区默认 Asia/Shanghai；每日北京时间 09:00 早间检查、16:30 增量检查。完整日报时间未定。每个接收人的选定范围通常创建两条 heartbeat：

| 逻辑标识 | 时间 | 范围及交付 |
| --- | --- | --- |
| morning | 09:00 | 选定范围；包含 policy 时提供每日一次页面和分析交接；tender-only 不打开政策页 |
| afternoon | 16:30 | 同范围，按实质变化报告；没有变化保持安静 |

both 范围在同一轮顺序检查政策和招标，输出分开，避免同一工作目录两个任务同时写台账。用户明确要求拆任务时使用不同独立工作目录，或先设计并验证运行锁；不能仅拆提示词让同一组导出并发覆盖。

创建前读取工作区 `data/automation_setup.json`，并检查本机已存在的匹配任务。自动化 ID 只视为定位线索，先用工具读取核对工作目录、范围、对话和时间。优先更新同一个任务，防止重复。登记为空但本机有匹配任务时，核实后补登记，不直接再建一套；不改其他工作目录的任务。

把 `Codex定时监测提示词.txt` 与该轮范围/时段合成完整、自然语言提示；不得残留 `{{WORKSPACE}}` 等模板标记。使用 kind=heartbeat，交付接收人的当前对话；只有用户明确要求每轮独立任务才使用 cron。notificationPolicy 保留用户选择；不要把通知偏好藏在提示词里。按工具 schema 表达重复规则，不让用户手填原始 RRULE。

仅工具返回成功后，把实际 ID、名称、scope、slot、时区、时间、实际 status、当前工作目录、创建/核验时间写进该工作区 `data/automation_setup.json`。保留用户已有字段和通知偏好。失败/排队记录真实状态，不能写 ACTIVE。不修改任何原安装人的定时任务。

最后读回工具结果确认每日时间、范围、工作目录和当前对话正确，明确接收人需要在其电脑保持运行所需的 Codex/网络/浏览器登录条件；以其当前 App 官方说明和实际运行测试为准。不同人员的本地台账彼此独立，不承诺自动共享团队审核结果或消除跨人重复；协作汇总需要另设共享台账方案。

## 本地验收与交付

- doctor 通过；画像已导入或缺项明确；工作目录具有两个空/有效台账、复核池、材料清单，未虚构人工完成。
- 至少一次真实来源检查；若网页工具或登录受阻，给出已完成部分与待处理项，不把示例入库冒充验收。
- 目标范围符合接收人分工，定时任务读回正确或清楚标待创建。
- 给接收人工作目录、服务网入口、以后如何“看未推荐/恢复候选/记录参与决定/升级”的简短用法。
